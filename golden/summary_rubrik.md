# Summary rubric — v1

One person labels (me). A summary passes only if it breaks none of these
rules. When a summary is hard to call, I add or sharpen the rule here
first, then label — never the other way round.

1. **Nothing the email does not say.** No invented details, causes, amounts,
   products or intentions. *Example: for c005 the model wrote "order";
   the email never mentions an order.*
2. **Names every issue the customer raised.** Dropping the second problem
   in a two-issue email is a fail even when the category is right.
3. **Language** The summary should be in the reader's language which is english,
   not in the customer's language.
4. **Summary length** The summary should include only the core customer's issue,
   not a full detailed dates, user's data or any other unnecessary information.

Passing is not "good". Passing is "breaks no rule". If a summary feels
wrong and breaks no rule, the rubric is missing a rule.
